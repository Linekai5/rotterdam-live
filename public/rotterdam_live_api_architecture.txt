## 1. Executive Summary & Core Architecture

The **Rotterdam Live API** (`rotterdam-live-api`) is an asynchronous, high-throughput geospatial platform engineered to power the real-time situational map of Rotterdam (`rott-live`). It serves as the single source of truth for all situational, municipal, commercial, environmental, meteorological, cultural event, and crowdness intelligence across the municipality of Rotterdam (Gemeentecode `0599`).

The database currently holds **over 396,400 spatial records** indexed with PostGIS GiST and PostgreSQL `pg_trgm` GIN indexes.

## 3. The Production-Grade Crowdness Engine & Real-Time Forecaster (Platform v1.9.0)

### Architectural Invariant: Zero In-Request Computation
The API endpoints return in **< 5ms** from Redis cache (**< 30ms** on cache-miss from indexed tables). 
**Never compute spatial joins, Gaussian curves, or historical regressions during client HTTP requests.**
- The background daemon (`rotterdam_live_worker`) handles 100% of the mathematical derivations, live residual logging, and forecast projections every 10 minutes.
- The API router (`app/api/v1/crowd.py`) strictly reads pre-compiled JSON snapshots from Redis and PostgreSQL.

### Quantitative Model Specification

Target metric: Normalized Crowdness Index $\mathcal{C} \in [0, 100]$.
- `0 - 25`: Quiet (Rustig)
- `26 - 50`: Moderate (Normaal)
- `51 - 75`: Busy (Druk)
- `76 - 100`: Saturated / Peak (Zeer druk / Piek)

#### A. Live Observation ($\mathcal{C}_{\text{live}}(d, t_0)$)
Run by the worker every 10 minutes:

1. **For districts with monitored parking garages ($N_{\text{garages}} > 0$):**
   $$\text{Occ}(d) = \frac{\sum_{i \in d} \text{occupied}_i}{\sum_{i \in d} \text{capacity}_i} \times 100$$
   $$\mathcal{C}_{\text{live}}(d, t_0) = \text{Clamp}\Big(0.75 \times \text{Occ}(d) + 0.15 \times \min(N_{\text{p2000}} \times 5, \, 20) + 0.10 \times \min(N_{\text{roads}} \times 5, \, 10) + \text{WeatherShift}_d(t_0), \, 0, \, 100\Big)$$
2. **For districts without monitored garages ($N_{\text{garages}} == 0$):**
   $$\mathcal{C}_{\text{live}}(d, t_0) = \text{Clamp}\Big(\hat{\mathcal{C}}_d(t_0) + \min(N_{\text{p2000}} \times 5, \, 20) + \min(N_{\text{roads}} \times 5, \, 10), \, 0, \, 100\Big)$$
   *(Note: This guarantees $\Delta_d(t_0) \equiv 0$ for sensorless districts unless localized incidents occur).*

#### B. Structural Baseline ($\hat{\mathcal{C}}_d(t)$)
$$\hat{\mathcal{C}}_d(t) = B_d(\text{dow}, \text{hour}) + \text{EventSurge}_d(t) + \text{WeatherShift}_d(t)$$

1. **Diurnal Baseline ($B_d(\text{dow}, \text{hour}) \in [0, 75]$):**
   - Calculated via 3-week Exponential Moving Average (EMA) from `crowd_telemetry_history` for $(dow, hour)$ when historical records $\ge 14$ days.
   - Seeded priors used if historical records $< 14$ days:
     * *Centrum / Retail:* Saturday peak 65 pts (13:00–17:00), Friday shopping evening 55 pts (18:00–21:00), weekday daytime 35–45 pts, night 10 pts.
     * *Residential (Noord, Kralingen, etc.):* Morning peak 40 pts (07:30–09:00), evening peak 45 pts (17:00–19:00), night 15 pts.
     * *Port / Industrial (Waalhaven, Botlek, etc.):* Weekday daytime 35 pts (07:00–16:00), night/weekends 5 pts.

2. **Event Surge with Exact Gaussian Profiles ($\text{EventSurge}_d(t) \in [0, 50]$):**
   For events in district $d$ or within 1.5 km buffer:
   $$\text{EventSurge}_d(t) = \min\left(50, \, \sum_{e \in E_d} \text{TierPoints}(e) \times \exp\left( - \frac{(t - t_{\text{peak}, e})^2}{2 \sigma_e^2} \right)\right)$$
   - **Tier Points:** $\text{HIGH} = 40\text{ pts}$ (Ahoy Arena, De Kuip, Marathon, North Sea Jazz), $\text{MEDIUM} = 20\text{ pts}$ (Luxor, De Doelen, Het Kasteel, Woudestein, Maassilo), $\text{LOW} = 8\text{ pts}$ (Rotown, local halls).
   - **Gaussian Temporal Parameters:**
     * *Stadium Matches (Football):* $t_{\text{peak}} = t_{\text{start}} + 45\text{ min}$, $\sigma = 50\text{ min}$.
     * *Concerts & Theatres (Ahoy / Luxor):* $t_{\text{peak}} = t_{\text{start}}$, $\sigma = 75\text{ min}$.
     * *Festivals & Outdoor Events:* $t_{\text{peak}} = t_{\text{start}} + (\text{duration} / 2)$, $\sigma = 180\text{ min}$.
     * *Default / Other:* $t_{\text{peak}} = t_{\text{start}}$, $\sigma = 60\text{ min}$.

3. **Weather Shift ($\text{WeatherShift}_d(t) \in [-15, +15]$ hard points):**
   - Rain $> 2.5\text{ mm/h}$: $-10\text{ pts}$ for outdoor districts; $+10\text{ pts}$ for indoor shopping hubs (Centrum, Zuidplein / Charlois).
   - Moderate rain ($0.5 - 2.5\text{ mm/h}$): $-5\text{ pts}$ outdoor, $+5\text{ pts}$ indoor hubs.
   - Pleasant ($18 - 25^\circ\text{C}$, dry, wind $< 4\text{ Bft}$): $+10\text{ pts}$ for recreational/terrace hubs (Centrum, Kralingen-Crooswijk).

#### C. Autoregressive Horizon Projection ($h \ge 0$)
1. **Live Residual at $t_0$:**
   $$\Delta_d(t_0) = \mathcal{C}_{\text{live}}(d, t_0) - \hat{\mathcal{C}}_d(t_0)$$
2. **Forecast at Horizon $h$ hours ($t = t_0 + h$):**
   $$\mathcal{C}_d(t_0 + h) = \text{Clamp}\Big(\hat{\mathcal{C}}_d(t_0 + h) + \Delta_d(t_0) \times e^{-0.5 h}, \, 0, \, 100\Big)$$
   *(Strictly guarantees that at $h=0$, $\mathcal{C}_d(t_0) \equiv \mathcal{C}_{\text{live}}(d, t_0)$ with zero double counting).*

## 4. Database Schema & Hard Constraints

### `crowd_telemetry_history`
```sql
CREATE TABLE crowd_telemetry_history (
    id BIGSERIAL PRIMARY KEY,
    district VARCHAR(128) NOT NULL,
    timestamp TIMESTAMPTZ NOT NULL, -- Truncated to 15-minute slot
    crowd_index FLOAT NOT NULL,
    crowd_status VARCHAR(64) NOT NULL,
    parking_occupancy_avg_pct FLOAT,
    active_events_count INTEGER DEFAULT 0 NOT NULL,
    precipitation_mm_h FLOAT DEFAULT 0.0 NOT NULL,
    temperature_c FLOAT,
    details JSONB NOT NULL DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ DEFAULT NOW() NOT NULL,
    CONSTRAINT uq_crowd_hist_district_time UNIQUE (district, timestamp)
);
CREATE INDEX idx_crowd_hist_district_time ON crowd_telemetry_history (district, timestamp DESC);
```

## 7. Frontend Integration Guide (Svelte & MapLibre GL)

### Consuming the /crowd Domain in Svelte & MapLibre GL
```javascript
import { 
  fetchLiveCrowdness, 
  fetchDistrictCrowdProfile, 
  fetchCrowdForecast, 
  installCrowdMapLayer 
} from '$lib/crowdClient.js';

// 1. Fetch master crowdness GeoJSON across all 19 districts (< 5ms)
const crowdGeoJSON = await fetchLiveCrowdness();

// 2. Install interactive choropleth layer on MapLibre GL
installCrowdMapLayer(map, { opacity: 0.5 });

// 3. Fetch single district profile with 24-hour horizon forecast series
const profile = await fetchDistrictCrowdProfile('Centrum');
console.log(profile.crowd_index, profile.crowd_status, profile.forecast);

// 4. Fetch forecast matrix
const forecast = await fetchCrowdForecast('Feijenoord');
```
